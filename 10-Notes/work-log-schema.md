# 업무 기록 속성 설계 (v1)

> 허브: [[work-log-system]] · 설계 회차: [[04-properties-templates-daily]]

슬랙으로 들어온 업무 기록 하나를 노트 하나로 만들 때, 맨 위에 붙이는 속성 규칙입니다.
헤르메스에게 분류를 시킬 때 이 문서를 그대로 규칙으로 줍니다.

## 설계 원칙

1. **적게 시작한다.** 칸이 많으면 AI가 억지로 채우다 틀린다
2. **값을 정해둔다.** 정해진 값 밖의 말은 쓰지 않는다
3. **AI가 채운 것은 사람이 확인한다.** `reviewed`로 표시한다

## 속성 목록

| 속성 | 타입 | 값 | 예시 | 필수 |
|---|---|---|---|---|
| `type` | 텍스트 | `지시` `회의` `이슈` `결정` `메모` 중 하나 | `지시` | ✅ |
| `created` | 날짜·시간 | 기록이 들어온 시각 | `2026-10-06T10:30` | ✅ |
| `source` | 텍스트 | 원본 위치 | `slack` | ✅ |
| `reviewed` | 체크박스 | 사람이 확인했으면 `true` | `false` | ✅ |
| `project` | 링크 | 프로젝트 허브 노트 | `"[[A프로젝트]]"` | |
| `people` | 목록(링크) | 관련된 사람 | `"[[김팀장]]"` | |
| `due` | 날짜 | 기한 | `2026-10-10` | |
| `status` | 텍스트 | `할일` `진행중` `완료` `보류` 중 하나 | `할일` | |

## 값을 고르는 기준 (`type`)

| 값 | 언제 |
|---|---|
| `지시` | 누군가 나(또는 팀)에게 일을 맡김 |
| `회의` | 여러 사람이 모여 논의한 내용 |
| `이슈` | 문제, 장애, 막힌 일 |
| `결정` | **확정된** 결론 (논의 중이면 `회의`) |
| `메모` | 위 어디에도 해당하지 않음 |

## 헤르메스가 지킬 규칙

- 정해진 값 밖의 말을 만들지 않는다. 애매하면 `메모`로 둔다
- **모르는 칸은 비워둔다. 추측해서 채우지 않는다** (특히 `due`, `people`)
- 날짜는 반드시 `YYYY-MM-DD` 형식 ("금요일" → 실제 날짜로 바꾸되, 확실하지 않으면 비움)
- `reviewed`는 항상 `false`로 만든다. `true`는 사람만 바꾼다
- "검토해 보자", "논의했다"는 `결정`이 아니다
- 본문 아래에 원본 메시지를 남긴다 (나중에 원문 대조용)

## 예시

```markdown
---
type: 지시
created: 2026-10-06T10:30
source: slack
reviewed: false
project: "[[A프로젝트]]"
people:
  - "[[김팀장]]"
due: 2026-10-10
status: 할일
---

- [ ] A 프로젝트 주간 보고서 작성 (기한 10/10)

## 원문
> 김팀장 지시: A 보고서 금요일까지
```
