## 2. 배운 것
- 폴더는 "누가, 어떤 상태로 쓰는 곳인가"로 나눈다

  | 폴더 | 용도 | 누가 쓰나 |
  |---|---|---|
  | `00-Inbox` | 일단 던져두는 곳 (정리 전) | 나 |
  | `10-Notes` | 정리된 노트 | 나 |
  | `90-Hermes` | 헤르메스 전용 작업 공간 | 헤르메스 (11회차부터) |

  - 앞의 숫자는 정렬 순서를 고정하기 위함
  - `90-Hermes`를 따로 두는 이유: 헤르메스에게 처음에는 이 폴더만 쓰기 권한을 줌 (최소 권한 원칙)

- 링크
  - `[[노트명]]` 연결, `[[노트명#제목]]` 특정 제목으로 이동
  - `[[없는노트]]`는 흐리게 보이고, 클릭하면 새 노트 생성 → 링크를 먼저 걸고 나중에 채울 수 있음
  - 폴더는 노트를 한 곳에만 두지만, 링크는 여러 곳과 동시에 연결 → 업무 지식 네트워크의 기본

- 백링크 = "누가 나를 가리키고 있나". 링크는 직접 걸지만 백링크는 자동으로 생김
  - 나중에 "A 프로젝트" 노트를 열면 관련 회의록·지시·이슈가 백링크로 모여 보임
- 그래프 뷰(`Cmd + G`): 노트는 점, 링크는 선. 연결이 많을수록 점이 큼
  - 가장 큰 점: `progress` — 나가는 링크 14개 + 들어오는 노트 9개 = 볼트의 "허브"
  - 허브 노트는 일부러 만드는 것. 4회차 이후 배울 MOC(목차 노트)가 같은 개념

- 분류 도구 4가지의 역할

  | 방법 | 질문 | 우리 시스템 예시 |
  |---|---|---|
  | 폴더 | 어떤 **상태**인가? | `00-Inbox`, `10-Notes` |
  | 속성 | 정해진 항목의 **값**은? | 종류, 프로젝트, 기한, 지시한 사람 |
  | 링크 | **무엇과** 관련 있나? | 회의록 ↔ 프로젝트 허브 ↔ 이슈 |
  | 태그 | 가볍게 **묶을** 표시는? | `#긴급`, `#보류` |

  - **원칙: 분류는 속성, 관계는 링크, 태그는 최소한** (태그는 `#회의`/`#미팅`처럼 쉽게 흐트러짐 → 쓸 태그 목록을 미리 정함)

- 임베드: `![[노트]]`는 내용을 그대로 보여줌, `![[노트#제목]]`은 그 부분만
  - 복사가 아니라 **원본을 보여주는 창** → 원본을 고치면 함께 바뀜
  - 우리 시스템: 위키 노트에 원본 메시지(`raw/`)를 임베드해서 근거를 바로 확인 (16회차 출처 확인의 기본 장치)

- 첨부파일 규칙: 위치는 `attachments/` 한 곳, 이름은 `날짜-주제-설명.확장자`
  - 설정 → 파일 및 링크 → 새 첨부파일의 기본 위치 → `attachments` (`app.json`의 `attachmentFolderPath`)
  - 파일 이름을 바꿔도 노트 안의 링크가 자동으로 고쳐짐 (`alwaysUpdateLinks: true`)
