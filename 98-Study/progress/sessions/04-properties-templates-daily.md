## 2. 배운 것
- 속성(Properties, frontmatter) = 노트 맨 위 `---` 사이에 적는 "이름: 값" 목록
- 본문은 사람이 읽는 내용, 속성은 **사람과 프로그램이 함께 읽는 정해진 칸**
- 속성 타입: 텍스트, 목록, 숫자, 체크박스, 날짜, 날짜·시간
- 추가 방법: `Cmd + ;` (또는 `Cmd + P` → "속성 추가"), 또는 첫 줄에 `---` 입력

- 속성 설계 원칙: ① 적게 시작 ② 값을 정해둠 ③ AI가 채운 건 사람이 확인(`reviewed`)
- 확정된 속성: `type`, `created`, `source`, `reviewed`(필수) / `project`, `people`, `due`, `status`(선택)
  - `project`, `people`은 링크 → 허브 노트에 백링크로 모임
  - `reviewed`는 헤르메스가 항상 `false` → "입력 → 처리 → 승인 → 반영"의 승인 단계

- 템플릿: 미리 만든 노트 틀을 버튼 하나로 끼워 넣기 (코어 플러그인 "템플릿", 이미 켜져 있었음)
  - 변수: `{{date}}`(오늘 날짜), `{{time}}`(지금 시각), `{{title}}`(노트 제목)
  - `templates/work-log.md`: [[work-log-schema]]의 속성 8개 + 할 일 + 원문 칸
  - 나중에 헤르메스 스킬의 출력 형식(`templates/`)으로도 그대로 쓰임

- 데일리 노트: 날짜 이름(`YYYY-MM-DD`)의 노트를 하루 하나 자동 생성
  - 우리 시스템 용도: **"오늘 들어온 업무 기록 모아보기"** 페이지
  - `templates/daily.md`의 검색 블록(```` ```query ````)이 오늘 날짜로 시작하는 기록을 자동으로 모아 보여줌
  - 위치: `20-Daily` 폴더

## 4. 막힌 점과 질문
- Q. 헤르메스를 적용할 때 `work-log-schema.md` 같은 설계 문서를 쓰고 헤르메스를 작동하면 되나?
  - A. 방향은 맞음. 다만 설계 문서는 절반. 헤르메스에게는 세 가지가 필요
    1. **규칙(무엇을)**: 설계 문서 [[work-log-schema]] — 옵시디언에 두고 한 곳에서만 관리
    2. **절차(어떻게)**: 헤르메스 **스킬**(`~/.hermes/skills/…/SKILL.md`: 언제 쓰나, 절차, 주의점, 검증) — 9회차
    3. **권한(어디까지)**: `90-Hermes`에만 쓰기 — 11회차
  - 그리고 **검증**: 샘플로 돌려보고 틀린 것 찾기 — 12·13회차
  - 참고: 헤르메스는 작업 폴더의 컨텍스트 파일(`.hermes.md`, `AGENTS.md`)도 자동으로 읽음 (공식 문서)
