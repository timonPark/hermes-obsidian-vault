## 2. 배운 것
- 헤르메스 메모리는 파일 두 개 (`~/.hermes/memories/`, 공식 문서)

  | 파일 | 내용 | 한도 |
  |---|---|---|
  | `USER.md` | 나에 대한 것: 선호, 말투, 기대 | 1,375자 |
  | `MEMORY.md` | 헤르메스의 메모: 환경, 규칙, 배운 것 | 2,200자 |

- 매우 작음 → **늘 기억해야 할 핵심만**. 지난 대화 찾기는 메모리가 아니라 세션 검색
- **모델이 `memory` 도구를 실제로 불러야 저장됨.** "기억해 둘게요"라는 말만으로는 저장되지 않음 → 파일을 직접 열어 확인
- 쓰기 승인 옵션(`write_approval`)이 있음: 저장 전에 사람이 확인 (`/memory pending`, `/memory approve`)
- 업무 기록은 메모리가 아니라 볼트에 (7회차: 메모리는 "나에 대한 기억", 볼트는 "업무에 대한 기록")

- 스킬 = 일하는 순서를 적은 `SKILL.md` (필수 속성 `name`, `description` / 본문: When to Use, Procedure, Pitfalls, Verification)
  - 설치된 스킬은 자동으로 `/스킬이름` 명령이 됨
  - `~/.hermes/config.yaml`의 `skills.external_dirs`로 **볼트 안 폴더의 스킬**도 불러올 수 있음 → 스킬 원본을 볼트(Git)에서 관리
- `work-log` 스킬 v0.1: 규칙 파일을 매번 읽고, 결과를 **보여주기만** 하고, "저장해" 승인 시에만 `90-Hermes`에 씀

## 4. 막힌 점과 질문
- Q. 스킬 결과가 어디에 있나? → 헤르메스 대화창(터미널)의 답장. 파일로는 승인 시에만 생김
- 팀장 실수: 상태 확인용 `git status`가 `.git/index.lock`을 남김 (팀장 환경은 삭제 권한 없음) → 학습자에게 `rm` 요청. 이후 `--no-optional-locks`로만 확인
- 발견: `work-log-schema.md` 끝에 `데이터 구조: [[api-key-policy]]` 한 줄이 실수로 붙어 있음 (14:12 수동 편집) → 삭제 요청
