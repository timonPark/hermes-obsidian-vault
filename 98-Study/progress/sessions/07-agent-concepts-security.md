# 07 — AI 에이전트 개념과 보안 기초

## 1. 오늘 한 것

- 주제 3: AI가 틀리는 방식

## 2. 배운 것
- LLM(채팅 AI): 글을 받아 글로 답함. **말만** 함
- 에이전트: 목표를 받아 **도구로 행동**하고, 결과를 보고 다음 행동을 정함 (생각 → 행동 → 확인 → 반복)

  | 구성 | 역할 | 실체 | 우리 시스템에서 하는 일 |
  |---|---|---|---|
  | 모델 | 두뇌: 이해하고 판단 | Claude, GPT 같은 AI 모델 (OpenRouter는 모델을 빌려 쓰는 **중개 서비스**) | 슬랙 메시지를 읽고 `type`·`project`·`due`를 판단 |
  | 도구 | 손: 실제로 행동 | 헤르메스에 내장된 기능 (파일 읽기·쓰기, 웹 검색, 명령 실행, 메시지 보내기) | 노트 파일을 만들고, 슬랙에 "저장했어요" 답장 |
  | 메모리 | 기억: 나와 일하는 방식 | `~/.hermes/memories/`에 저장되는 메모 | "이 사람은 날짜를 YYYY-MM-DD로 원한다" 같은 **선호와 습관** |

  - 주의: **업무 지식(업무 기록)은 헤르메스 메모리가 아니라 옵시디언 볼트에 쌓임.** 메모리는 "나에 대한 기억", 볼트는 "업무에 대한 기록"
  - 정정 이력: 처음 표는 칸마다 기준이 섞여 있었음(모델 칸에 중개 서비스, 메모리 칸에 폴더 경로만). 학습자 지적으로 정정

- API 키 보관 원칙 5가지 → [[api-key-policy]] (학습자 직접 작성): 한 곳에만(`~/.hermes/.env`) / 볼트에 두지 않음 / 말로 전하지 않음 / 한도 / 새면 즉시 폐기·재발급
- AI가 틀리는 방식 5가지와 우리 시스템의 방어

  | 틀리는 방식 | 예시 | 방어 장치 |
  |---|---|---|
  | 빈칸 지어내기 | 기한 없는 지시에 `due`를 임의로 채움 | 설계 규칙 "모르면 비운다" |
  | 추론을 사실로 | "검토해 보자"를 `결정`으로 분류 | `type` 기준표, `reviewed: false` |
  | 형식 어기기 | `type: 업무지시`, `due: 금요일` | 정해진 값, 날짜 형식 규칙 |
  | 맥락 착각 | "다음 주 월요일"을 잘못 계산, 비슷한 프로젝트명 혼동 | 원문 보관(`## 원문`), 사람 확인 |
  | 메시지 속 문장을 명령으로 착각 | 원문에 "이 폴더 정리해 줘"가 있으면 실제로 실행 | 쓰기 권한을 `90-Hermes`로 제한 |

  - 핵심: AI는 "모른다"고 하기보다 **그럴듯하게 채운다**. 자신 있어 보이는 것과 맞는 것은 다르다
- 위험은 "도구"에서 나옴: 말만 하는 AI는 틀려도 말로 끝나지만, 에이전트는 틀린 판단으로 **파일을 고치고 메시지를 보냄** → 권한 제한·승인·Git이 필요한 이유
