# 헤르메스 & 옵시디언 교육 커리큘럼

> 대상: 두 도구를 처음 접하는 팀원 (사전 지식 없음)
> 강사: 팀장 (역할 정의는 [[team-lead-role-rule]] 참고)
> 기간: 약 4~5주 · 총 16회차 · 회차당 30~60분

---

## 이 순서로 배우는 이유

1. **옵시디언 먼저, 헤르메스는 나중에**
   에이전트는 결국 "사람이 하던 정리를 대신 해주는 도구"입니다. 내가 노트를 어떻게 정리하는지 모르면 에이전트에게 시킬 수도, 결과를 검토할 수도 없습니다.
2. **중간에 기초 체력 회차를 넣습니다**
   헤르메스는 터미널에서 설치하고 API 키로 AI 모델에 연결합니다. 처음이면 여기서 가장 많이 막히기 때문에 별도 회차로 다룹니다.
3. **연동은 작게, 업무 적용은 천천히**
   전용 폴더 하나와 자동화 하나로 시작해서, 믿을 수 있게 되면 범위를 넓힙니다.

## Part 0. 오리엔테이션

### 0회차 — 학습 방법과 큰 그림
- **목표**: 무엇을 왜 배우는지 이해하기
- **배울 내용**
  - 헤르메스 = 일하는 쪽(에이전트), 옵시디언 = 기억하는 쪽(노트 저장소)
  - 두 도구를 함께 쓰면 업무가 어떻게 바뀌는지 (현업 사례)
  - 학습 방식: 설명 → 실습 → 노트 기록 → 다음 회차에 리뷰
- **실습**: 학습 폴더(`study/hermes-obsidian`) 확인, 역할 규칙 파일 읽기
- **완료 기준**: 두 도구의 역할을 내 말로 한 문장씩 설명할 수 있다

---

## Part 1. 옵시디언 기초

### 1회차 — 마크다운 기초
- **목표**: 옵시디언 노트의 문법인 마크다운으로 글을 쓸 수 있다
- **배울 내용**: 제목(`#`), 목록, 굵게/기울임, 체크박스, 표, 코드 블록, 인용
- **실습**: 자기소개 노트를 마크다운으로 작성
- **완료 기준**: 서식을 보지 않고 제목·목록·표를 쓸 수 있다

### 2회차 — 옵시디언 설치와 볼트
- **목표**: 볼트를 만들고 노트를 다룰 수 있다
- **배울 내용**
  - 설치, "폴더를 볼트로 열기", `.obsidian` 설정 폴더의 의미
  - 노트 만들기·이동·이름 바꾸기, 검색, 빠른 전환(Cmd+O), 명령 팔레트(Cmd+P)
  - 편집 모드와 읽기 모드
- **실습**: `hermes-obsidian` 폴더를 볼트로 열고 `00-Inbox`, `10-Notes`, `90-Hermes` 폴더 만들기
- **완료 기준**: 마우스 없이 노트를 찾고 열 수 있다

### 3회차 — 연결: 링크, 백링크, 태그, 그래프
- **목표**: 노트끼리 연결해 "지식 네트워크"를 만든다
- **배울 내용**
  - 내부 링크 `[[노트명]]`, 특정 제목 링크 `[[노트명#제목]]`
  - 백링크(이 노트를 가리키는 노트들), 그래프 뷰
  - 태그 `#태그`와 폴더의 차이 (언제 무엇을 쓰는지)
- **실습**: 지금까지 쓴 노트 3개 이상을 서로 링크하고 그래프 뷰로 확인
- **완료 기준**: 폴더·태그·링크를 어떤 기준으로 나눠 쓰는지 설명할 수 있다

### 4회차 — 구조화: 속성(frontmatter), 템플릿, 데일리 노트
- **목표**: 사람과 에이전트 모두 읽기 좋은 "규칙 있는 노트"를 만든다
- **배울 내용**
  - 노트 맨 위 속성(Properties / frontmatter): `type`, `status`, `tags`, `created`
  - 핵심 플러그인: 템플릿, 데일리 노트
  - 왜 이게 나중에 헤르메스에게 중요한지 (에이전트가 분류·검색하는 기준이 됨)
- **실습**: "학습 노트" 템플릿을 만들고 데일리 노트로 오늘 학습 기록하기
- **완료 기준**: 템플릿으로 속성이 포함된 노트를 바로 만들 수 있다

### 5회차 — 볼트 설계와 백업
- **목표**: 오래 써도 무너지지 않는 볼트 구조와 안전장치를 갖춘다
- **배울 내용**
  - 폴더 설계 원칙 (인박스 → 정리 → 보관), 파일명 규칙
  - 커뮤니티 플러그인: 설치 방법과 주의점 (검증되지 않은 플러그인 위험)
  - Git으로 볼트 버전 관리 (에이전트가 잘못 고쳐도 되돌릴 수 있게)
- **실습**: 볼트 구조 문서(`README.md`) 작성, Git 저장소로 만들고 첫 커밋
- **완료 기준**: 노트 하나를 실수로 지워도 Git으로 복구할 수 있다

## Part 2. 기초 체력

### 6회차 — 터미널과 AI 에이전트 개념
- **목표**: 헤르메스 설치 전에 필요한 기초 지식을 갖춘다
- **배울 내용**
  - 터미널 기본: `pwd`, `ls`, `cd`, `mkdir`, 경로, 환경 변수
  - LLM(언어 모델)과 에이전트의 차이: 도구 사용, 메모리, 자율 실행
  - 모델 제공자와 API 키, 사용량 과금 구조
  - 보안 기초: API 키는 절대 노트·채팅·Git에 올리지 않는다
- **실습**: 터미널로 학습 폴더에 이동해서 파일 목록 보기, 용어 노트 정리
- **완료 기준**: "에이전트 = 모델 + 도구 + 메모리"를 예시로 설명할 수 있다

## Part 3. 헤르메스 기초

### 7회차 — 헤르메스 설치와 모델 연결
- **목표**: 내 컴퓨터에서 헤르메스와 첫 대화를 한다
- **배울 내용**
  - 설치 방법 (CLI / 데스크톱 앱), 설치 후 생기는 `~/.hermes` 폴더
  - 모델 선택과 연결, 비용과 성능 트레이드오프
  - 사내에서 쓸 때 확인할 것: 보안 정책, 허용된 모델·서비스
- **실습**: 설치 → 모델 연결 → "자기소개 해줘" 첫 대화
- **완료 기준**: 헤르메스를 직접 실행하고 종료할 수 있다

### 8회차 — 헤르메스 핵심 구조: 메모리, 스킬, 도구, 프로필
- **목표**: 헤르메스가 "어떻게 기억하고 일하는지" 이해한다
- **배울 내용**
  - 내장 도구 (파일 읽기·쓰기, 웹 검색, 명령 실행 등)와 권한
  - 메모리: 나를 기억하는 방식, 메모리 확인·수정
  - 스킬: 반복 작업을 절차로 저장해 재사용
  - 프로필: 용도별 에이전트 분리 (처음에는 하나로 충분)
- **실습**: 내 업무 스타일을 메모리에 알려주고, 간단한 스킬 하나 만들기
- **완료 기준**: 메모리와 스킬의 차이를 설명할 수 있다

### 9회차 — 메신저 연결과 스케줄
- **목표**: 컴퓨터 앞에 없어도 에이전트에게 일을 시킨다
- **배울 내용**
  - 게이트웨이: 메신저(예: 텔레그램, 슬랙)로 헤르메스와 대화
  - 스케줄(cron): 정해진 시간에 자동 실행
  - 사내 메신저 연동 시 보안 검토 포인트
- **실습**: 메신저로 메모 보내기, "매일 아침 9시 인사" 스케줄 등록
- **완료 기준**: 스케줄을 등록·확인·삭제할 수 있다

---

## Part 4. 연동

### 10회차 — 헤르메스 ↔ 옵시디언 연결
- **목표**: 헤르메스가 볼트의 정해진 폴더만 읽고 쓰게 한다
- **배울 내용**
  - 연결 방식 비교: 폴더 직접 접근 / 옵시디언 플러그인(사이드바 채팅)
  - 권한 범위 설정: `90-Hermes` 전용 폴더에서 시작, `.obsidian` 폴더는 접근 금지
  - 옵시디언 볼트(사람의 지식)와 헤르메스 메모리(에이전트의 기억)는 다르다
- **실습**: 헤르메스가 `90-Hermes`에 노트를 만들게 하고, 옵시디언에서 확인
- **완료 기준**: 허용 범위 밖의 파일은 헤르메스가 수정하지 못함을 확인했다

### 11회차 — 첫 자동화: 인박스 정리와 데일리 요약
- **목표**: 실제로 쓸모 있는 자동화 하나를 완성한다
- **배울 내용**
  - 인박스 정리: 날것의 메모 → 속성·태그 추가 → 알맞은 폴더로 이동 제안
  - 데일리 요약: 오늘 만든 노트를 모아 하루 요약 노트 생성
  - "제안 → 사람 승인 → 반영" 흐름 만들기
- **실습**: 메신저로 메모 3개 보내기 → 헤르메스가 정리 → Git diff로 변경 검토
- **완료 기준**: 일주일 동안 자동화를 돌리고 문제점을 기록했다

## Part 5. 업무 적용

### 12회차 — 회의록 파이프라인
- **목표**: 회의 메모를 규격화된 회의록으로 바꾼다
- **배울 내용**: 회의록 템플릿 (참석자, 결정 사항, 액션 아이템, 담당자, 기한), 액션 아이템 추출, 관련 프로젝트 노트 자동 링크
- **실습**: 실제(또는 가상) 회의 메모로 회의록 3건 만들기
- **완료 기준**: 회의 후 10분 안에 회의록을 공유할 수 있다

### 13회차 — 기술 문서, ADR, 장애 회고
- **목표**: 팀의 기술 지식을 쌓이는 자산으로 만든다
- **배울 내용**: ADR(아키텍처 의사결정 기록), 장애 회고(Postmortem) 템플릿, 초안 작성은 에이전트, 검토와 확정은 사람
- **실습**: 최근 기술 결정 하나를 ADR로 작성
- **완료 기준**: 템플릿 2종을 만들고 각각 1건 이상 작성했다

### 14회차 — 볼트 기반 지식 검색과 주간 리포트
- **목표**: 쌓인 노트를 질문으로 꺼내 쓴다
- **배울 내용**: "지난달 X 관련 결정이 뭐였지?" 같은 질의, 출처 노트 링크로 답하게 하기, 주간 리포트 자동 생성(스케줄)
- **실습**: 볼트에 질문 5개 해보고, 답의 정확도 점검표 작성
- **완료 기준**: 매주 자동으로 생성되는 리포트가 있다

---

## Part 6. 운영과 졸업

### 15회차 — 보안, 품질 점검, 팀 확산
- **목표**: 개인 도구를 팀 단위로 안전하게 운영한다
- **배울 내용**
  - 보안 체크리스트: 기밀·개인정보, API 키, 외부 모델 전송 범위
  - 품질 점검: 에이전트 산출물 샘플링 리뷰, 실패 사례 기록
  - 팀 확산: 공통 볼트 구조, 템플릿 공유, 가이드 문서
- **실습**: 내 환경의 보안 체크리스트 점검
- **완료 기준**: 팀원에게 설명할 수 있는 운영 가이드 초안이 있다

### 16회차 — 졸업 과제
- **목표**: 배운 것을 내 업무에 맞게 조합한다
- **과제**: 내 업무 중 반복되는 일 하나를 골라 헤르메스 + 옵시디언 워크플로로 설계·구현
- **산출물**: 워크플로 설계서(문제, 흐름도, 권한 범위, 검토 절차, 효과) + 10분 발표
- **완료 기준**: 2주 이상 실제로 사용한 결과를 공유한다
