## 이 순서로 배우는 이유

1. **옵시디언 먼저, 헤르메스는 나중에.** 내가 노트를 어떻게 정리하는지 알아야 에이전트에게 시키고, 결과를 검토할 수 있습니다.
2. **기초 체력 회차를 따로 둡니다.** 헤르메스는 터미널에서 설치하고 API 키로 모델에 연결합니다. 처음 배우는 사람이 가장 많이 막히는 곳이라 두 회차로 나눴습니다.
3. **만드는 것보다 되돌리는 것이 중요합니다.** 자동화는 반드시 틀립니다. 틀렸을 때 발견하고, 멈추고, 되돌리는 훈련을 별도 회차로 둡니다.

## 모든 자동화의 기본 설계 원칙

> **입력 → 처리 → 승인 → 반영 → (실패 시) 복구**

- 에이전트가 만든 결과는 사람이 승인하기 전까지 확정하지 않습니다.
- 반영 전후 변경 내용은 항상 Git diff로 확인합니다.
- 외부 발송(메일, 메신저, 공유 문서)은 자동으로 하지 않습니다.

## Part 0. 오리엔테이션

### 0회차 — 학습 방법과 큰 그림
- **목표**: 무엇을 왜 배우는지 이해한다
- **배울 내용**
  - 헤르메스 = 일하는 쪽(에이전트), 옵시디언 = 기억하는 쪽(노트 저장소)
  - 두 도구를 함께 쓸 때 업무가 어떻게 바뀌는지 (현업 사례)
  - 학습 방식: 설명 → 수업 중 실습 → 회차 사이 과제 → 다음 회차 리뷰
- **수업 중 실습**: 학습 폴더 구조 확인, 역할 규칙 파일과 이 커리큘럼 읽기
- **회차 사이 과제**: 내 업무 중 "반복되고 귀찮은 일" 3가지 적어오기
- **완료 기준**: 두 도구의 역할을 각각 한 문장으로 쓰고, 반복 업무 3가지를 적었다

## Part 1. 옵시디언 기초

### 1회차 — 마크다운 기초
- **목표**: 옵시디언 노트의 문법인 마크다운으로 글을 쓴다
- **배울 내용**: 제목(`#`), 목록, 굵게·기울임, 체크박스, 표, 코드 블록, 인용
- **수업 중 실습**: 자기소개 노트를 마크다운으로 작성
- **회차 사이 과제**: 0회차의 반복 업무 3가지를 표로 정리
- **완료 기준**: 참고 자료 없이 제목·목록·표·체크박스가 들어간 노트 1개를 작성했다

### 2회차 — 옵시디언 설치, 볼트, 검색
- **목표**: 볼트를 열고 노트를 빠르게 찾는다
- **배울 내용**
  - 설치, "폴더를 볼트로 열기", `.obsidian` 설정 폴더의 의미
  - 노트 만들기·이동·이름 바꾸기, 빠른 전환(Cmd+O), 명령 팔레트(Cmd+P)
  - 검색 문법: `path:`, `tag:`, `file:`, 제외 조건(`-`), 문구 검색(`"..."`)
- **수업 중 실습**: `hermes-obsidian` 폴더를 볼트로 열고 `00-Inbox`, `10-Notes`, `90-Hermes` 폴더 만들기
- **회차 사이 과제**: 노트 5개 이상 작성하기
- **완료 기준**: 검색 문법을 써서 서로 다른 조건의 검색 5개를 직접 해봤다

### 3회차 — 연결: 링크, 백링크, 태그, 임베드, 첨부파일
- **목표**: 노트끼리 연결해 지식 네트워크를 만든다
- **배울 내용**
  - 내부 링크 `[[노트명]]`, 제목 링크 `[[노트명#제목]]`, 블록 링크 `[[노트명#^id]]`
  - 임베드 `![[노트명]]`: 다른 노트나 이미지를 본문에 끼워 넣기
  - 백링크, 그래프 뷰, 태그와 폴더의 차이
  - 노트 이름을 바꾸면 링크가 자동으로 업데이트되는 설정
  - 첨부파일 저장 위치 설정과 파일명 규칙
- **수업 중 실습**: 노트 3개를 서로 링크하고, 이미지 1개를 첨부해 임베드하기
- **회차 사이 과제**: 기존 노트 하나의 이름을 바꿔 링크가 유지되는지 확인
- **완료 기준**: 링크 3개 이상, 임베드 1개, 첨부파일 1개가 규칙에 맞는 위치에 있다

### 4회차 — 구조화: 속성, 템플릿, 데일리 노트
- **목표**: 사람과 에이전트 모두 읽기 좋은, 규칙 있는 노트를 만든다
- **배울 내용**
  - 속성(Properties, frontmatter)과 타입: 텍스트, 날짜, 목록, 체크박스
  - 핵심 플러그인: 템플릿(날짜·제목 변수), 데일리 노트
  - 이것이 나중에 헤르메스에게 중요한 이유: 에이전트가 분류하고 검색하는 기준이 됨
- **수업 중 실습**: `type`, `status`, `tags`, `created` 속성 4개를 가진 "학습 노트" 템플릿 만들기
- **회차 사이 과제**: 매일 데일리 노트로 학습 기록 남기기
- **완료 기준**: 템플릿으로 속성 4개가 포함된 노트 3개를 만들었다

### 5회차 — 볼트 설계, Git, 백업, 동기화
- **목표**: 오래 써도 무너지지 않는 구조와, 잘못돼도 되돌릴 수 있는 안전장치를 갖춘다
- **배울 내용**
  - 폴더 설계 원칙 (인박스 → 정리 → 보관), 파일명 규칙
  - 셋은 서로 다릅니다

    | 개념 | 목적 |
    |---|---|
    | Git | 변경 이력 확인, 비교, 복구 |
    | 동기화 | 여러 기기 간 파일 맞추기 |
    | 백업 | 원본이 손상됐을 때 별도 사본으로 복구 |

  - `.gitignore` 작성 (`.obsidian/workspace*`, 대용량 첨부, 비밀정보 파일 제외)
  - 커밋 전 `git diff`로 변경 확인, 잘못 수정된 노트 복구
  - 커뮤니티 플러그인 설치 방법과 위험 (검토되지 않은 플러그인)
- **수업 중 실습**: 볼트 구조 문서(`README.md`) 작성 → Git 저장소 만들기 → 첫 커밋 → 노트를 일부러 망가뜨리고 복구
- **회차 사이 과제**: Git과 별개의 백업 방법 하나를 정해 적용
- **완료 기준**: 잘못 수정한 노트를 Git으로 복구했고, Git 외 백업 1개를 갖췄다

## Part 2. 기초 체력

### 6회차 — 터미널과 파일 경로
- **목표**: 헤르메스 설치에 필요한 터미널 기초를 익힌다
- **배울 내용**: `pwd`, `ls`, `cd`, `mkdir`, `cat`, 절대 경로와 상대 경로, 숨김 파일, 환경 변수 개념
- **수업 중 실습**: 터미널로 볼트 폴더에 이동해서 파일 목록 보기, Git 상태 확인
- **회차 사이 과제**: 터미널 명령어 치트시트 노트 만들기
- **완료 기준**: 터미널만으로 볼트 폴더에 이동하고, 노트 1개의 내용을 출력했다

### 7회차 — AI 에이전트 개념과 보안 기초
- **목표**: 에이전트가 무엇이고, 무엇을 조심해야 하는지 이해한다
- **배울 내용**
  - LLM(언어 모델)과 에이전트의 차이: 에이전트 = 모델 + 도구 + 메모리
  - 모델 제공자, API 키, 사용량 과금 구조
  - AI가 틀리는 방식: 사실과 다른 내용, 추론을 사실처럼 말하기
  - 보안 기초: API 키는 노트·채팅·Git에 넣지 않고 환경 변수나 사내 승인 저장소에 둔다
  - 사내 확인 사항: 허용된 모델과 서비스, 외부 전송 가능한 정보 범위
- **수업 중 실습**: 용어 노트 정리, 사내 AI 사용 가이드 확인
- **회차 사이 과제**: 내 반복 업무 3가지에 들어가는 정보의 민감도 적어오기
- **완료 기준**: 에이전트 구성요소 3가지를 예시와 함께 쓰고, API 키 보관 원칙을 노트에 정리했다

## Part 3. 헤르메스 기초

### 8회차 — 헤르메스 설치, 모델 연결, 기능 확인
- **목표**: 내 컴퓨터에서 헤르메스와 첫 대화를 하고, 실제 기능을 확인한다
- **배울 내용**
  - 설치 방법 (CLI 또는 데스크톱 앱), 설치 후 생기는 `~/.hermes` 폴더
  - 모델 선택과 연결, 비용과 성능의 트레이드오프
  - API 키를 환경 변수로 설정하기
- **수업 중 실습**: 설치 → 모델 연결 → 첫 대화 → 아래 기능 확인표 채우기
- **회차 사이 과제**: 일주일 사용 비용 기록하기
- **완료 기준**: 헤르메스를 실행·종료할 수 있고, 기능 확인표를 모두 채웠다

### 9회차 — 핵심 구조: 메모리, 스킬, 도구, 프로필
- **목표**: 헤르메스가 어떻게 기억하고 일하는지 이해한다
- **배울 내용**
  - 내장 도구 (파일 읽기·쓰기, 웹 검색, 명령 실행 등)와 권한
  - 메모리: 나를 기억하는 방식, 메모리 확인과 수정
  - 스킬: 반복 작업을 절차로 저장해 재사용
  - 프로필: 용도별 에이전트 분리 (처음에는 하나로 충분)
- **수업 중 실습**: 내 업무 스타일을 메모리에 알려주고, 간단한 스킬 하나 만들기
- **회차 사이 과제**: 만든 스킬을 3번 이상 사용하고 결과 기록
- **완료 기준**: 메모리 내용을 직접 열어 확인·수정했고, 스킬 1개를 만들어 3번 실행했다

### 10회차 — 메신저 연결과 스케줄
- **목표**: 컴퓨터 앞에 없어도 에이전트에게 일을 시킨다
- **배울 내용**
  - 게이트웨이: 메신저로 헤르메스와 대화
  - 스케줄(cron): 정해진 시간에 자동 실행, 중복 실행 주의
  - 메신저 연동 시 보안 검토: 대화 내용이 어디에 저장되는지
- **수업 중 실습**: 메신저로 메모 보내기, 간단한 스케줄 등록
- **회차 사이 과제**: 스케줄이 예정대로 실행됐는지 3일간 기록
- **완료 기준**: 스케줄을 등록·확인·삭제했고, 실행 기록을 확인했다

---

## Part 4. 연동

### 11회차 — 헤르메스 ↔ 옵시디언 연결과 권한
- **목표**: 헤르메스가 볼트의 정해진 폴더에서만 읽고 쓰게 한다
- **배울 내용**
  - 연결 방식 비교: 폴더 직접 접근 / 옵시디언 플러그인(사이드바 채팅)
  - 권한 범위: `90-Hermes` 전용 폴더에서 시작, `.obsidian` 폴더 접근 금지
  - 옵시디언 볼트(사람의 지식)와 헤르메스 메모리(에이전트의 기억)는 다르다
- **수업 중 실습**: 헤르메스가 `90-Hermes`에 노트를 만들게 하고 옵시디언에서 확인 → 허용 폴더 밖에 쓰기를 시도해서 막히는지 테스트
- **회차 사이 과제**: 연결 설정과 권한 범위를 노트로 문서화
- **완료 기준**: 허용 폴더 밖 쓰기가 실패하는 것을 직접 확인하고 기록했다

### 12회차 — 첫 자동화: 인박스 정리와 데일리 요약
- **목표**: 실제로 쓸모 있는 자동화 하나를 설계 원칙대로 만든다
- **배울 내용**
  - 인박스 정리: 날것의 메모 → 속성·태그 추가 → 폴더 이동 "제안"
  - 데일리 요약: 오늘 만든 노트를 모아 하루 요약 노트 생성
  - 입력 → 처리 → 승인 → 반영 흐름 구현
- **수업 중 실습**: 테스트 메모 3건으로 자동화 실행 → Git diff로 변경 검토 → 승인 후 커밋
- **회차 사이 과제**: 실제 메모로 5~7일 사용하고, 이상한 결과를 모두 기록
- **완료 기준**: 테스트 3건을 diff 검토 후 반영했고, 사용 기록 노트가 있다

### 13회차 — 장애 훈련: 실패를 발견하고 되돌리기 *(신규)*
- **목표**: 자동화가 틀렸을 때 발견하고, 멈추고, 되돌릴 수 있다
- **배울 내용**: 지난 회차 과제의 실패 사례 리뷰, 아래 상황별 대응
  - 잘못된 폴더에 파일이 생성된 경우
  - 기존 노트를 덮어쓴 경우
  - 중복 노트가 만들어진 경우
  - 링크가 깨진 경우
  - 사실과 다른 요약이 만들어진 경우
  - 스케줄이 중복 실행된 경우
  - API 한도 초과나 연결 실패
- **수업 중 실습**: 위 상황 중 3가지를 일부러 만들고 각각 발견 → 중단 → 복구 → 재실행
- **회차 사이 과제**: 내 자동화의 "복구 절차서" 작성
- **완료 기준**: 중단, 재실행, 이전 상태 복구를 각각 1번 이상 직접 수행했다

---

## Part 5. 업무 적용

### 14회차 — 회의록 파이프라인
- **목표**: 회의 메모를 검증된 회의록으로 바꾼다
- **배울 내용**
  - 회의록 템플릿: 참석자, 결정 사항, 액션 아이템, 담당자, 기한
  - 액션 아이템 추출, 관련 프로젝트 노트 자동 링크
  - 검증: 발언자·결정 사항·담당자를 원문과 대조, 확정 전 사람 승인
- **수업 중 실습**: 회의 메모로 회의록 3건 생성 → 원문 대조 → 오류 기록
- **회차 사이 과제**: 실제 회의 1건에 적용
- **완료 기준**: 회의록 3건을 원문과 대조해 오류 목록을 작성했고, 자동 생성 회의록을 그대로 외부 공유하지 않았다

### 15회차 — 기술 문서, ADR, 장애 회고
- **목표**: 팀의 기술 지식을 쌓이는 자산으로 만든다
- **배울 내용**
  - ADR(아키텍처 의사결정 기록), 장애 회고(Postmortem) 템플릿
  - 초안 작성은 에이전트, 검토와 확정은 사람
  - 사실과 모델의 추론을 구분해 표시하기
- **수업 중 실습**: 최근 기술 결정 하나를 ADR로 작성
- **회차 사이 과제**: 장애 회고 템플릿으로 과거 사례 1건 정리
- **완료 기준**: 템플릿 2종을 만들고 각각 1건 이상 작성했다

### 16회차 — 볼트 기반 지식 검색과 주간 리포트
- **목표**: 쌓인 노트를 질문으로 꺼내 쓰고, 답을 검증한다
- **배울 내용**
  - "지난달 X 관련 결정이 뭐였지?" 같은 질의
  - 답변에 출처 노트 링크 포함하기, 출처가 없으면 "확인할 수 없다"고 답하게 하기
  - 주간 리포트 자동 생성 (스케줄)
- **수업 중 실습**: 볼트에 질문 5개 → 각 답을 출처 노트와 대조해 정확도 점검표 작성
- **회차 사이 과제**: 주간 리포트 1회 자동 생성 후 검토
- **완료 기준**: 질문 5개 모두 출처 링크 포함 여부와 정확도를 기록했고, 주간 리포트가 1회 이상 생성됐다

---

## Part 6. 운영과 졸업

### 17회차 — 보안, 품질 점검, 팀 확산
- **목표**: 개인 도구를 팀 단위로 안전하게 운영한다
- **배울 내용**
  - **정보 등급 분류**: 공개 / 사내 일반 / 내부 제한 / 개인정보 / 고객·영업·보안 기밀
  - **보안 체크리스트**
    - 어떤 정보가 외부 모델로 전송되는가
    - 모델 제공자가 데이터를 학습에 사용하는가
    - API 키를 어디에 저장하는가
    - 노트, 프롬프트, Git 이력에 비밀정보가 남지 않는가
    - 메신저 연동 시 대화 내용이 어디에 저장되는가
    - 외부 발송 전에 사람이 승인하는가
  - 품질 점검: 산출물 샘플링 리뷰, 실패 사례 기록
  - 팀 확산: 공통 볼트 구조, 템플릿 공유, 가이드 문서
- **수업 중 실습**: 내 환경에 보안 체크리스트 적용, Git 이력에서 비밀정보 검색
- **회차 사이 과제**: 팀원용 운영 가이드 초안 작성
- **완료 기준**: 체크리스트 6개 항목을 모두 점검했고, 운영 가이드 초안이 있다

### 18회차 — 졸업 과제 발표
- **목표**: 배운 것을 내 업무에 맞게 조합한다
- **과제**: 0회차에 적은 반복 업무 중 하나를 골라 헤르메스 + 옵시디언 워크플로로 설계·구현 (16회차부터 준비 시작)
- **산출물**: 워크플로 설계서 (문제, 흐름도, 권한 범위, 승인 절차, 복구 절차, 효과) + 10분 발표
- **완료 기준**: 1주 이상 실제로 사용한 결과를 발표했다
- **후속 리뷰**: 2주 후 운영 결과를 다시 공유
